The part most long-prompt projects quietly get wrong

01

Five million lines is 75 million tokens

The largest context window on the market holds about one million. A corpus this size cannot be fed to any model, on any provider, at any price.

02

So "paste this and an app appears" is not a claim that runs

It describes something that has never executed once. Loomstack does not make that claim. The corpus is not the interface.

03

The router is the interface

It narrows a task to the entity slices that task needs, attaches the contract that governs them, and prints a pack an agent can act on. One task, one pack.

Type a task. Watch the corpus narrow.

This runs the same two-stage narrowing the CLI does: rank shards by term overlap, pull the matching entity slices, cut them to a line budget. Drag the budget and the pack recomposes.

# Loomstack context pack
Task: checkout with idempotent payment capture

## Global contract
- Integer minor units for money. Never float.
- Every write carries an idempotency key, scoped per tenant, 24 h window.
- Authorization is asserted in the handler, not delegated to the gateway.
- Every mutation writes its audit row inside the same transaction.
- Soft delete via deleted_at. No physical delete outside the purge job.
- Optimistic locking on version. Reject stale writes with 409.

- payments.ledger.ledger_transfer.create auth=bearer scope=payments:create
- payments.ledger.ledger_transfer.create idempotent=header
- payments.ledger.ledger_transfer.create success=201
- payments.ledger.ledger_transfer.create timeout=4s retries=0

- payments_ledger_transfer.currency char(3) :: ISO 4217

- payments_ledger_transfer.version int :: optimistic lock counter
#### states

- transition active -> settled guard=ledger_guard_4 actor=service
- transition held -> review guard=ledger_guard_3 actor=analyst
